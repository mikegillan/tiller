## Architecture and compatibility decisions

### Keep coordination shared

Do not recreate the orchestration tools for each CLI. The daemon's HTTP MCP server already
provides `spawn`, `send`, `read`, `report_outcome`, etc. An adapter supplies node-scoped auth,
lifecycle reporting, native prompt submission, launch/session handling and transcript decoding.

All node HTTP requests use:

- `TL_ENDPOINT` as the daemon base URL;
- `Authorization: Bearer <contents of TL_TOKEN_FILE>`;
- `X-TL-Node: <TL_NODE_ID>`.

Never give an agent adapter the human/admin token.

### Preserve legacy records

`NODE_KINDS` now includes `claude`, `agent`, `terminal`. `Harness` currently includes `claude`
and `pi`. Records without a harness retain Claude behavior. New Pi records use
`{ kind: "agent", harness: "pi" }`.

Generic agent children inherit their parent's harness unless explicitly selected. Legacy
`kind: "claude"` still explicitly means Claude. Terminal nodes cannot select a harness.

`HarnessAdapter` covers capabilities, restriction validation, launch arguments/environment,
working directory and transcript location. Claude wraps the existing launch code. Pi starts
interactively with the extension and an explicit session file; `effort` maps to `--thinking`.

### Reliable messaging, not terminal guessing

Pi registers Tiller's existing MCP server and polls `/inbox`. Delivery uses `/claim`, native
`pi.sendUserMessage`, and `/ack` on observed acceptance. Ordinary messages stay unclaimed while
busy so the sender can withdraw them; steers abort the run before submission once idle.

**A void `sendUserMessage` return is not acceptance.** Pi can fail asynchronously or consume an
input without starting a run. The bridge tracks submitted versus accepted separately and
confirms the exact prompt through `before_agent_start`. Ambiguous submissions are not resent.
Ack failures retry the receipt, not the prompt.

Pi's adapter declares a required native inbox: the daemon queues messages there even before
the first poll, rather than falling back to Claude-specific terminal composer heuristics.

### Lifecycle and sessions

- `/hook` reports session metadata, accepted user prompts, tool activity and active-run UI dialogs.
- `/mod-event` reports run start, final settlement, context usage and cumulative spend.
- State-critical HTTP events are serialized to prevent ordering races.
- `agent_settled`, not `agent_end`, is the authoritative final boundary.
- Final assistant `stopReason` distinguishes error/abort/normal completion.
- Idle extension-command dialogs do not falsely transition a node to working.

Pi files live at `<TL_HOME>/sessions/<rootId>/agents/<nodeId>/<Tiller-session-id>.jsonl`, not
under `nodes/<id>` (which close deletes). `TL_SESSION_ID` preserves Tiller's minted id even
though Pi generates a different UUID inside the file header.

Pi JSONL decoding follows the active `id`/`parentId` branch and handles `toolCall` blocks.
Resume, restart, archive reads and follow-up are wired through the selected harness. A Pi
follow-up currently reuses the archived transcript path. Restart keeps previous-session files
in that directory. Retention protects registered roots and directories referenced by
registered nodes' transcript paths.

Pi's `/new`, `/resume`, `/fork` and `/tree` are blocked for managed sessions; use Tiller's
controls. Pi `/reload` remains available.

### Safety and worktrees

Pi starts directly inside a Tiller-created worktree and does not require Claude workspace
trust. The `.claude/worktrees/<nodeId>` convention remains for compatibility with existing
worktree reconciliation.

Repo setup/teardown and completion-gate commands require explicit trust. Added human-only CLI
operations `tl trust --cwd PATH` and `tl untrust --cwd PATH`, backed by
`<TL_HOME>/trusted-projects.json`. Existing Claude trust is still honored. Removing Tiller
trust does not revoke a separate Claude trust record. This is distinct from Pi's own
project-resource trust and permission policy.

Pi rejects Claude `permissionMode` and preset `tools`, `disallowedTools`, `maxTurns` rather than
silently weakening restrictions. Prompt-only presets work. Pi session forking is unsupported.

Background Git reads now use `GIT_OPTIONAL_LOCKS=0`; this fixed existing worktree-test races
where status refreshes competed with commits for the index lock. Required mutation locks are
not disabled.

   unconfirmed; the daemon renews claimed-message TTL while the bridge is live, so steady-state

   branches/transcript decoding behind adapter methods before adding the next harness.

   declare unsupported capabilities explicitly, and investigate each CLI's native event/prompt
